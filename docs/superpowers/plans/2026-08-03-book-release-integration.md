# Full Book Release Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development for implementation reviews, superpowers:verification-before-completion before any release claim, and superpowers:finishing-a-development-branch before merging or pushing.

**Goal:** Превратить успешно reviewed приватный корпус в exact public reader bundle, безопасно влить оба репозитория, развернуть GitHub Pages и доказать публичный результат post-deploy smoke-проверкой.

**Architecture:** Private `yu-book` owns `C/T/E/F` and produces the only accepted generated roots. Public `yu` records pre-book base `B`, then validates and commits the bundle and Astro UI as one auditable release range `B..P`. Clean main worktrees fast-forward the verified feature branches; the public push starts GitHub Pages. A production smoke compares live routes and release identity with the checked-in manifest; failure atomically reverts the entire `B..P` range and proves the release-owned tree is back at `B` before redeploy.

**Tech Stack:** Git worktrees, Node.js 24, npm, GitHub CLI/API, GitHub Actions/Pages, HTTP smoke tests.

**Prerequisites:** The private platform and editorial plans are complete through clean evidence commit `E` with gate `agent-reviewed`. Public Tasks 1–3 are complete on the linear feature branch; the pre-publication SHA `B` is their clean Task 3 tip, and Public Tasks 4–9 remain blocked on `F`. This plan creates `F`, resumes the public plan, then performs release integration.
